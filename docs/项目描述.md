# 宝宝成长记录 · 项目描述（PRD）

> 移动端优先的网页应用：记录宝宝喂奶、待办事项与图文备忘。
> 设计目标：**清新放松的视觉** + **极致便捷的操作**（能点就不打字，能一步就不两步）。

---

## 1. 项目背景

新手父母需要频繁记录宝宝吃奶时间和奶量，并据此判断「下次该什么时候喂」。同时日常还有大量与宝宝相关的待办（打疫苗、买尿布等，常需要截图存档）和零碎备忘（儿保医嘱、生长数据等，常需要配图）。

本应用用一个移动端网页解决这三类记录需求，打开即用、无需安装，核心操作均为一两步完成。

**参考架构**：与 family-recipe-uni Web 版相同（Vue 3 + Vite + Cloudflare Pages Functions + D1），图片压缩后以 base64 存 D1，全程免费，不依赖任何第三方图床。

## 2. 功能清单

### 2.1 喂奶记录（首页 Tab）

| 功能 | 说明 |
|------|------|
| 记一笔 | 记录吃奶时间 + 奶量（ml）+ 备注（可选）。时间默认当前，可修改 |
| 快捷奶量 | 常用奶量 chips（默认 30 / 60 / 90 / 120 ml，新生儿 30ml 为高频值），**点一下即填入**；chips 可在设置中增删自定义 |
| 快捷备注词 | 常用备注 chips（如「亲喂」「瓶喂」「拍嗝」「剩 10ml」），点选即填入，可自定义增删 |
| 记录列表 | 按天分组展示：时间、奶量（大数字）、备注；左滑删除 |
| 上次喂奶 | 页面顶部常驻「距上次喂奶 X 小时 Y 分」 |
| 到点提醒 | 页面打开/回到前台时，对比「上次喂奶时间 + 设定间隔」与当前时间，超时则在首页顶部显示**页面内提示条**（柔和橙色系，仅视觉提示，无倒计时/震动/提示音） |
| 间隔设置 | 喂奶间隔（小时），默认 3 小时 |

### 2.2 待办事项（Tab）

| 功能 | 说明 |
|------|------|
| 新增待办 | 标题 + 可选截图/图片（相册选择或粘贴截图，客户端 Canvas 压缩） |
| 勾选完成 | 卡片左侧圆形勾选框，点一下切换完成状态；完成项划线置灰并自动沉底 |
| 图片查看 | 缩略图点击放大预览 |
| 删除 | 左滑或编辑页删除 |

### 2.3 备忘录（Tab）

| 功能 | 说明 |
|------|------|
| 新增备忘 | 标题 + 多行正文 + 多张图片（压缩上传） |
| 列表 | 图文卡片流，有图显示首图缩略图，按更新时间倒序 |
| 详情/编辑 | 点开查看完整图文，可直接编辑保存 |
| 删除 | 编辑页删除 |

### 2.4 设置

- 喂奶间隔（小时）
- 展示时长（小时）
- 快捷奶量管理（增删，上限 8 个）
- 快捷备注词管理（增删，上限 8 个）
- 快捷事件管理（增删，上限 8 个）
- 设置项存 D1（`settings` 表单行 JSON），进设置页 / 回到前台时从云端拉取，换设备自动一致；`localStorage` 仅作首屏缓存与离线兜底
- 首次升级时若云端还没有设置，会把本机现有配置上传一次，不用默认值覆盖

## 4. 交互细节

### 4.1 便捷性设计（核心）

- **快捷奶量 chips**：点选填入输入框，再点其他 chip 即替换；也可直接在数字键盘输入任意值
- **快捷备注词**：点选追加到备注，再点取消
- **记一笔默认时间 = 当前**：大多数情况下只需「点奶量 chip → 保存」，两步完成
- **触控区 ≥ 44px**，所有可点元素放大热区
- **弹层从底部上滑**，拇指可达区域内完成全部输入

### 4.2 到点提醒逻辑

```
打开页面 / 页面从后台回到前台（visibilitychange）时：
  elapsed = now - 最近一次喂奶时间
  if elapsed >= 设定间隔 → 显示提示条「宝宝该吃奶啦，距上次已 X 小时 Y 分」
  else → 提示条隐藏，顶部显示「距上次喂奶 X 小时 Y 分」
```

仅页面内视觉提示，不请求通知权限、无声音震动。

### 4.3 图片处理（沿用参考项目）

- 选择图片后客户端 Canvas 压缩：待办用长边 ≤ 1280px / quality 0.7；备忘一次最多 9 张、全部塞在同一行，用 1024px / quality 0.65，并带「超过 160KB 就降质量重编」的目标体积循环，单张约 80~160KB
- 压缩后 base64 随记录一起存 D1
- **列表接口不返回图片本体**，返回 `/api/xxx/image/:id` 地址按需加载；图片接口带 ETag，未修改返回 304
- 服务端体积护栏：单张 > 400KB 或合计 > 1.7MB 返回 413（D1 单行硬上限 2MB，超了会报 500）

## 5. 技术架构

| 层 | 技术 |
|------|------|
| 前端 | Vue 3 + Vite 5 + Vue Router 4，移动优先，系统字体栈 |
| 后端 API | Cloudflare Pages Functions |
| 数据库 | Cloudflare D1（SQLite） |
| 图片 | Canvas 压缩 + base64 存 D1 |
| 设置 | D1（`settings` 单行 JSON）+ localStorage 缓存 |
| 部署 | GitHub + Cloudflare Pages Git 集成，push main 自动构建部署 |

### 5.1 数据模型（D1）

```sql
CREATE TABLE feedings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  feed_time TEXT NOT NULL,        -- ISO 时间，吃奶时间
  amount_ml INTEGER NOT NULL,     -- 奶量
  note TEXT DEFAULT '',
  created_at TEXT NOT NULL
);

CREATE TABLE todos (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  image TEXT DEFAULT '',          -- base64，单张
  done INTEGER DEFAULT 0,
  created_at TEXT NOT NULL,
  completed_at TEXT
);

CREATE TABLE memos (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  content TEXT DEFAULT '',
  images TEXT DEFAULT '[]',       -- base64 JSON 数组，多图
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- 设置：全局单租户，永远只有 id=1 这一行，内容整体存 JSON
CREATE TABLE settings (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  json TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### 5.2 API 设计（Pages Functions）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/feedings` | GET / POST | 列表（按天分组数据）/ 新增 |
| `/api/feeding/:id` | DELETE | 删除一条喂奶记录 |
| `/api/todos` | GET / POST | 列表（不含图片本体）/ 新增 |
| `/api/todo/:id` | POST / DELETE | 勾选/编辑 / 删除 |
| `/api/todo/image/:id` | GET | 待办图片（ETag） |
| `/api/memos` | GET / POST | 列表（不含图片本体）/ 新增 |
| `/api/memo/:id` | GET / POST / DELETE | 详情（`?raw=1` 含原图）/ 编辑 / 删除 |
| `/api/memo/image/:id/:idx` | GET | 备忘第 idx 张图（ETag） |
| `/api/events` | GET / POST | 事件列表 / 新增 |
| `/api/event/:id` | DELETE | 删除一条事件 |
| `/api/settings` | GET / POST | 读取设置（`empty=true` 表示云端还没有）/ 全量覆盖写入 |
| `/api/cleanup` | POST | 按服务端存储的展示时长清理过期喂奶记录（无设置时跳过） |

性能约定（同参考项目）：列表/详情默认不返回图片本体，备忘详情返回 `/api/memo/image/:id/:i` 地址数组，保存时地址原样回传、服务端按索引取回原图（只有新增图进请求体，避免几 MB 的 base64 全量重传导致弱网 408）；前端请求 30 秒超时（body > 120KB 放宽到 60 秒），GET / DELETE 失败自动重试 1 次，POST 默认不重试。

## 6. 部署方案（Git 集成自动部署）

1. 代码推送至 GitHub 仓库
2. Cloudflare Dashboard → Pages → Create a project → Connect to Git，选择该仓库
3. 构建配置：构建命令 `npm run build`，输出目录 `dist`
4. 创建 D1 数据库 `baby-tracker-db` 并执行 `schema.sql`：
   ```
   npx wrangler d1 create baby-tracker-db
   npx wrangler d1 execute baby-tracker-db --file=./schema.sql
   ```
5. Pages 项目 → Settings → Functions → D1 database bindings：变量名 `DB`，绑定 `baby-tracker-db`
6. 之后每次 `git push` 到 main 分支即自动构建部署，无需手动操作
